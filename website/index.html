Google Ads,
from the terminal.

Agent-first CLI and a k9s-style TUI for the Google Ads API v25. Browse campaigns, asset groups, and assets. Every command documents itself.

Install Source

Built for agents. Fine for humans.

Self-describing

adscli --help and adscli schema --json are the docs. No extra manual required.

Structured I/O

Global --json. Errors on stderr. Exit codes 0–5. Mutations need --yes.

k9s-style TUI

Drill campaigns → asset groups → assets. Filter, enable, pause. Bare adscli needs a TTY.

Browser SSO

adscli login is Desktop OAuth + PKCE. Every build ships the branded adscli client.

Install

Homebrew (macOS and Linux)

brew install dvaldivia/tap/adscli

From a GitHub Release tarball

VERSION=0.0.3 OS=linux ARCH=x86_64
curl -sSL -o adscli.tar.gz \
  "https://github.com/dvaldivia/adscli/releases/download/v${VERSION}/adscli_${OS}_${ARCH}.tar.gz"
tar -xzf adscli.tar.gz
install -m 0755 adscli /usr/local/bin/adscli

From source

cargo install --git https://github.com/dvaldivia/adscli adscli

Try it

adscli version --json
adscli schema --json
adscli login
adscli customers list --json
adscli campaigns list --json --limit 20

Auth

Every adscli binary ships a shared Desktop OAuth client. adscli login uses it unless you set ADSCLI_CLIENT_ID / ADSCLI_CLIENT_SECRET (or the same keys in a config file). You still click Allow as yourself. The Desktop secret is public-by-design — extracting it does not open anyone’s Ads account.

The Google Ads developer token is not shipped. Set ADSCLI_DEVELOPER_TOKEN before API calls. Check adscli auth status --json for has_oauth_client, oauth_from_bundle, and has_developer_token.

Full behavior: adscli login --help and the README.
